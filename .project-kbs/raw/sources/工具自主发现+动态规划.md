工具自主发现 + 动态规划（大模型 Agent 领域核心概念详解）
先一句话总览：
工具自主发现 = Agent 不用人预先写死工具列表，自己识别、检索、理解可用工具；
动态规划（Agent 层面，非传统算法 DP） = 根据任务进展，动态调整工具调用顺序、选择、执行策略，不是固定流程。
二者结合，就是具备开放式工具生态、自适应任务流程的智能体，也是当前 AutoGPT、OpenAI Agents SDK、Claude Tool Use、Mem0+Tooling 等方案的核心方向。
区分两个容易混淆的名词：
算法层面动态规划 DP（最优子结构、状态转移）
Agent 动态规划（本文重点：动态规划 = 动态规划执行路径）
一、工具自主发现（Tool Autonomous Discovery）
1. 定义
   传统 LLM 工具调用（Function Calling）模式：
   开发者静态预先注册全部函数 / 工具，把工具 Schema 一次性塞进系统提示词；模型只能从给定集合里挑选，不知道外部新增工具。
   工具自主发现打破边界：
   Agent不依赖人工预配置完整工具清单，能够自主完成：
   工具检索 → 工具语义匹配 → 工具 Schema 解析 → 可用性校验 → 按需纳入候选集。
2. 完整能力链路（五层流程）
   需求语义抽取
   解析用户目标，提炼需要具备什么能力：
   例：用户 “查武汉今日油价”→ 需求能力：油价实时查询 API。
   工具空间检索（发现）
   检索外部工具仓库 / 向量库 / 插件市场（工具元数据库）；
   工具元数据一般存储：工具名称、功能描述、入参、权限、调用成本、适用场景。
   相关性排序与筛选
   使用 Embedding 语义匹配，过滤无关工具；解决 “同名不同功能、相似工具” 冲突。
   自主解析工具契约（Schema）
   自动读懂入参类型、必填项、枚举约束、返回结构，不需要人工整理 Prompt。
   可行性预判
   判断权限、参数是否能从当前上下文补齐，无法补齐则规划追问用户。
3. 两种实现架构
   方案 A：检索式发现（工业主流）
   搭建工具向量知识库
   每条工具 = {工具描述 + JSON Schema + 标签}，向量化存储。
   Agent 遇到任务 → 向量检索 Top-N 候选工具，动态注入本次会话可用函数列表。
   [表情] 优点：易落地、支持上万工具、新增工具无需重启 Agent；
   [表情] 缺点：检索存在召回偏差，容易漏工具、匹配到错误工具。
   方案 B：自主探索式发现（前沿研究）
   Agent 可主动访问工具注册中心、浏览接口文档、甚至尝试探测 API，无预先构建向量库；类似人类上网查找可用服务。
   代表项目：AutoGPT 早期工具探索、Web Research Agent。
   [表情] 开放式极强；[表情] 成本高、稳定性差、容易产生无效调用。
4. 和传统 Function Calling 关键对比
   表格
   维度	传统静态工具调用	工具自主发现
   工具集合	启动前固定，运行期间不能新增	运行时动态检索、加载工具
   扩新成本	新增工具必须修改代码 + 重启 Agent	新增工具入库即可，Agent 自动感知
   适用规模	少量工具（<20 个）	大规模工具市场（几十～上万工具）
   典型场景	企业内部固定业务机器人	通用智能助手、开放插件生态
5. 现存痛点
   工具语义歧义问题（两个工具描述相近，能力不同）
   检索召回不足，最优工具没有被检索出来
   缺少工具可靠性评价机制（搜到工具但接口已失效）
   大量候选工具输入上下文，引发上下文窗口膨胀
   二、Agent 动态规划（Dynamic Planning for Agent）
   [表情] 重点澄清：
   这里不完全等于算法 Dynamic Programming，更多指代动态任务规划（Dynamic Task Planning），业内经常简称为动态规划。
   如果是论文语境，部分工作会融合经典 DP 算法做路径价值评估。
1. 静态规划 VS 动态规划
   静态规划（传统链式 Agent）
   预先写死流程：
   工具A → 工具B → 工具C
   典型：LangChain SequentialChain、固定 RAG 流水线
   特点：无论中间结果如何，执行顺序不变；遇到异常无法调整。
   Agent 动态规划核心思想
   不预设完整执行链路，随着每一步观测（工具返回结果、用户反馈、失败报错）持续重新规划下一步动作。
   闭环循环：
   理解目标 → 当前状态观测 → 规划候选动作(工具) → 执行工具 → 更新环境状态 → 重新规划
2. 动态规划包含三大核心能力
   路径动态生成
   初始只确立最终目标，不规定步骤数量、调用次序。
   示例：用户需要 “对比武汉、麻城房价，整理报表”
   Agent 第一步先规划：查两地新房均价；拿到数据后，第二步再规划调用表格生成工具；中途数据缺失则临时增加爬虫工具。
   动态分支与回退
   工具调用失败（接口超时、参数错误）→ 动态更换备选工具、重试或调整参数；
   发现当前方向无法达成目标 → 回溯，放弃现有路径，选择其他方案。
   终止条件自适应判断
   不是固定执行 N 轮就停止；
   Agent 自主判断：信息充足 / 无法继续 / 已满足用户需求 → 停止工具调用，整理结果回复。
3. 技术实现路线（两大流派）
   路线 1：LLM 原生规划（主流工程方案）
   利用大模型自身推理做规划，代表：ReAct、Plan-and-Solve、Self-Ask
   每一轮 Prompt 要求模型输出：
   当前进度 + 还缺少哪些信息 + 下一步选择哪个工具 + 参数
   简单 Prompt 范式示例：
   plaintext
   【任务目标】xxx
   【已获取信息】xxx
   【可用工具】[本次检索发现的工具集合]
   规则：
1. 评估当前信息是否足够回答用户；足够则直接输出答案
2. 不足，请选择合适工具，生成调用参数
3. 如果多条路径可行，优先选择成本更低、时效性更高的工具
   路线 2：融合经典动态规划算法（学术方向）
   把 Agent 行动建模成马尔可夫决策过程 MDP：
   状态 S：当前上下文、已收集信息
   动作 A：调用某个工具
   回报 R：距离任务完成的收益
   使用 DP 价值迭代，计算不同工具序列的预期收益，选出最优执行路径。
   代表：GPT+DP 规划、RL+Agent 框架；缺点推理成本极高，极少直接商用。
4. 动态规划常见策略模式
   递进式规划：先粗规划整体步骤，执行中细化每一步；
   并行候选规划：同时构思多条可行路径，优先尝试成功率最高路线；
   失败重规划：工具报错、信息矛盾时触发重新规划。
   三、【组合】工具自主发现 + 动态规划（完整智能体运行流程）
   把两者串联起来，看完整运行时序，这也是你做 Agent 开发最需要理解的实战流程：
   plaintext
1. 用户输入任务
2. 需求解析 → 提取所需能力描述
3. 【工具自主发现阶段】
   向量检索工具库 → 筛选、校验，得到本轮候选工具集
4. 【动态规划启动】
   基于目标+现有信息+候选工具，决策下一步动作
5. 执行选定工具，获取观测结果
6. 更新全局状态
7. 循环回到动态规划：
   情况1：信息不足 → 继续选用工具（可再次触发工具发现，补充检索更多工具）
   情况2：当前工具都无法解决 → 重新发起更广范围工具发现
   情况3：任务完成 → 结束工具调用，整理输出
   举一个完整业务例子直观理解
   用户需求：统计近一个月湖北光伏发电量，并生成趋势图
   需求拆解：需要【光伏数据查询】【绘图生成工具】
   工具自主发现：检索工具库，找到：
   工具 1：湖北省电力数据 API；工具 2：matplotlib 图表生成；工具 3：Excel 导出
   第一轮动态规划：优先调用电力 API 获取月度数据
   API 返回数据成功 → 再次动态规划：下一步调用绘图工具生成走势图
   图表生成完毕，评估信息完整 → 终止流程，汇总结果
   异常分支演示（体现两大模块协同价值）：
   假设【电力数据 API 调用失败】
   动态规划模块检测执行失败；
   主动触发新一轮工具自主发现，检索备选工具：全网能源资讯爬虫；
   重新规划路径：使用爬虫采集公开数据替代原 API。
   如果没有工具自主发现：一旦预设 API 失效，Agent 直接卡死，没有备选方案；
   如果只有静态流程没有动态规划：即便搜到爬虫工具，程序也不会主动切换执行路径。
   四、工程落地难点（开发避坑要点）
1. 工具自主发现难点
   检索精度问题：向量相似≠功能可用，容易误匹配；
   候选工具过多，塞满上下文，引发模型混淆；
   [表情] 优化：增加工具筛选器、限制 Top-K、增加工具能力打分；
   缺乏工具时效管理（接口下线、参数变更后元数据未更新）。
2. 动态规划难点
   大模型容易出现无限循环：反复调用同一个工具；
   [表情] 优化：状态记录历史动作，禁止无意义重复调用；设置最大迭代轮次兜底；
   长任务下规划一致性变差，容易遗忘原始目标；
   [表情] 优化：每轮规划强制回顾顶层用户目标；
   多目标任务容易跑偏，子任务优先顺序混乱。
3. 二者结合的典型架构参考
   plaintext
   用户输入
   ↓
   意图&需求抽取
   ↓
   工具发现模块（向量检索 + 工具过滤）
   ↓
   动态规划引擎（LLM Planner）
   ↓
   工具调度执行器
   ↓
   结果写入状态记忆
   ↑ ↓
   【循环】是否达成目标？
   否 → 重新规划 / 重新检索更多工具
   是 → 结果整理输出
   五、延伸区分易混淆概念
   动态规划（Agent 任务规划） ≠ 算法 DP
   工程开发绝大多数场景指动态任务路径规划；只有强化学习、决策优化论文才会结合状态价值 DP 算法。
   工具自主发现 ≠ RAG
   RAG 检索文档；工具发现检索可执行函数 / API 能力元数据，目标是产生函数调用，而非文本引用。
   自主发现 ≠ 工具多选
   多选是给定集合里挑选；发现是主动向外搜索可用集合。
